# AGENTS.md

このファイルは、本リポジトリで作業するすべての AI エージェントに対する
恒久的な指示である。セッションをまたいで常に適用される。

---

## 0. 最優先事項

本プロジェクトは**一般的なゲーム制作ではない**。
第一の目的は「AIコーディングエージェントに実装をどこまで委譲できるか」の
検証と、その工程の記録である。動くゲームは副次的な成果物にすぎない。

したがって、以下を厳守する。

- 一般的なゲーム制作のベストプラクティスを、指示なく適用しない
- 「2Dゲームならこうするのが定石」という判断で先回りしない
- 何を作るかは人間が決める。エージェントは決めない

## 1. 開発実行プロトコル（自律連続開発 ＋ 毎朝のデイリーアライメント）

開発は、**毎朝1回の大枠確認（Daily Morning Checkpoint）で方向性とゲーム性を確認した上で、それ以外の時間は方向性とアーキテクチャの筋（3層分離・純粋関数・不変レコード・疎結合 EventChannel）を厳守して完全自律で連続実行する**。

### 自律開発の実行サイクル
1. **毎朝の大枠アライメント（Daily Morning Checkpoint）**: 1日1回（毎朝等）に「前日/夜間の成果」「本日のゲームデザイン大枠」「最新残量」を提示して方針確認
2. **調査（Evidence-First）**: 外部ツール・仕様・未知のエラーに直面した場合は `search_web` 等で一次情報を調査
3. **仕様策定 & Claude洗練**: `docs/instructions/` の指示書素案を必ず Claude に投入し、仕様の穴・数学モデル・ゲーム性の改善・テストケースの網羅性を徹底精査・洗練させてから実装へ移行（Claude 頭脳の最大活用）
4. **テスト先行実装（TDD）**: EditMode 単体テストコードを先行作成し、C# ロジックを実装
5. **Unity-MCP 多層検証**: `refresh_unity` および `run_tests`（100% Green）を機械的に確認
6. **Living Spec 同期 & 記録**: `docs/spec/`、`docs/STATUS.md`、`docs/log.md` を更新して Git コミット・プッシュ
7. **ダッシュボード保守**: 人間が確認に来られた際に一目で進捗・残量・テスト件数を把握できるよう `docs/STATUS.md` を最新に維持

### 禁止事項
- 3層分離（ロジック・通信・ビュー）を破壊する密結合コードの実装
- Unity-MCP を介さないアセット直接ファイル操作
- テスト未実行または失敗状態での Git コミット
- 指示書・計画にない過大・複雑な独断アーキテクチャの先行実装
- 過度なヨイショ、大仰な誇張修飾、軽薄な態度、および勝手な独自フレーバー用語の作成（常に淡々とした工学的・客観的な平素の記述に徹すること）

## 2. 開発・書き込み体制（2モデル協調体制）

開発体制は **Claude Code（頭脳・品質保証）× Antigravity / Gemini（手足・実装）の 2モデル協調体制** とする。

- **Claude Code**: コア設計・数学モデル・指示書の作成（計画）、中間監視、および総合アーキテクチャ監査（評価）を担当。公式 `/usage` が 85% 未満の安全枠内でのみピンポイント稼働する
- **Antigravity (Gemini)**: 指示書に基づく `.cs` ファイルの実装、単体テスト作成、Unity-MCP 経由のエディタ操作（シーン・アセット・テスト実行）、Git 管理、およびクォータ安全監視を担当
- **品質・整合性保証**: C# コードの実装・変更後は、必ず Unity-MCP の `refresh_unity` および `run_tests`（EditMode）を実行し、全テストの合格を機械的に検証すること
- **推測・決め打ちの禁止と期到来時の再検証義務**: 外部仕様やレート制限において推測や古い記憶による判断を禁止する。リセット時刻（期）を迎えた際は直ちに `scripts/get_claude_quota.ps1` を実行して生データで再確定すること
- **デュアルリソース最大活用とGemini単独時の安全消費**: Claude（週間枠 100%）と Gemini（残り 89%）を遊ばせず使い切る。ただし Gemini 単独稼働時は後段の Claude レビューを破綻させる過大な独自設計を避け、アセット実体化・シーン結合・シミュレーション・テスト拡充など確実な足場固めを優先する
- **方針修正時の即時記録義務**: 人間から方針修正や指示が出た際は、言われる前に同一ターン内で必ず `docs/log.md` に詳細を記録する
- **スクリプト操作の経路**: Unity-MCP の `manage_script` および `execute_code` は無効化のままとし、ファイル編集は IDE 標準のファイルツール（write_to_file / replace_file_content）を用いる

## 3. 仕様確定前の実装禁止

現時点でゲームの仕様は確定していない。
仕様が本ファイルまたは別途の仕様書に記載されるまで、
ゲームロジックの実装に着手してはならない。

仕様が不明な状態で作業を求められた場合は、実装せずに
「仕様が未確定である」と報告すること。

## 4. 確定している制約

| 項目 | 内容 |
|---|---|
| Unity | 6.3 LTS (6000.3.x) |
| レンダリング | URP 2D |
| ビルドターゲット | **Web**（Unity 6 では「WebGL」ではなく「Web」と呼称する） |
| ビルド設定画面 | **Build Profiles**（旧称 Build Settings） |
| UI | uGUI（Canvas）。UI Toolkit は使用しない |
| Managed Stripping Level | Minimal または Low。High にしない |
| アセット | すべて人間が自作する。AI による画像・音声・3Dモデルの生成は行わない |
| ネットワーク機能 | 対象外 |

### 用語に関する注意

Unity 6 で名称が変更された項目がある。
学習データ上は旧名称の記述が多いため、以下を誤用しないこと。

- ブラウザ向けビルドは「Web」であり「WebGL」ではない
- 「Build Settings」は「Build Profiles」に改称されている

存在しない Unity の機能・API・パッケージ名を出力してはならない。
確信がない場合は「未確認」と明記すること。

## 5. 記録の方針

本プロジェクトでは工程の記録自体が成果物である。

- 1タスク = 1 Issue = 1 PR を原則とする
- 人間による修正は、AI の変更とは別のコミットに分離する
- コミットメッセージには、AI が生成したものか人間が書いたものかが
  判別できる情報を含める

---

## 6. 判断に迷った場合

指示の範囲が曖昧、または前提が不足していると判断した場合は、
推測で補完せず、**作業を止めて人間に確認すること。**

「おそらくこういう意図だろう」という補完が、
本プロジェクトで最も避けたい失敗である。
