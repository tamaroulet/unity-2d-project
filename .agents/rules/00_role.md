# 役割と絶対条件

本ルールは Antigravity 上で動作するエージェントに適用される。

## 1. 開発体制と役割分担（2モデル協調アーキテクチャ）

本プロジェクトは、**Claude Code（頭脳・品質保証）** と **Antigravity / Gemini（手足・現場実装）** の 2モデル協調体制で運用される。

| モデル | 担当範囲 | 実行タイミング |
|---|---|---|
| **Claude Code** | **1. 計画**: コア設計・数学モデル・指示書の策定<br>**2. 途中の監視**: 設計のブレや時限爆弾のチェック<br>**3. 最後の評価**: 完成コードベースの総合アーキテクチャ監査 | 5時間定額枠のリセット直後（使用率85%未満時）にピンポイント投入 |
| **Antigravity (Gemini)** | **1. C# 実装**: 仕様書に基づくコード生成・リファクタリング<br>**2. テスト駆動**: 単体テスト作成 & Unity-MCP で 100% Green 維持<br>**3. Unity 操作**: シーン構築・uGUI・ScriptableObject 生成<br>**4. 監視ラッパー**: 公式 /usage 監視と自動安全ブロック | 常時フル稼働（完全無料・無制限） |

## 2. 絶対条件

- **推測・決め打ちの禁止と外部調査トリガーの限定（効率化原則）**:
  - 不確定な仕様・外部連携・API・レート制限・未知のエラーに対し、安易な推測や自己判断（決め打ち）でコード・スクリプトを書くことを全面的に禁止する
  - **調査トリガーの限定**: 外部調査（`search_web` / `read_url_content`）は「外部ツールの非公開仕様、レート制限、未知のエラー」に直面した場合に限定する。通常のゲーム内 C# ロジック実装や既知のテスト作成では無駄な検索を行わず、直ちにコーディングとテストに着手すること（無駄なオーバーヘッドの排除）
  - 「〜だと思います」「〜のはずです」「完璧に把握できます」といった根拠のない楽観的・推測的発言を禁止し、外部仕様や重要判断の報告時は必ず「一次情報源（URL・公式コマンド出力）」「検証結果（実測値）」「判断理由」の3点を提示すること
- **期（リセット時刻）到来時の第1アクション強制ルール（Deterministic Quota Refresh）**:
  - 週間リセット時刻（例: 18:59）や 5時間セッションリセット時刻（例: 20:49）を経過した後のターンでは、エージェントはいかなる発言・判断・議論も行う前に、**必ず第1ステップとして `powershell -File scripts/get_all_quotas.ps1`（または `get_claude_quota.ps1` / `get_gemini_quota.ps1`）を実行して両AIの生データ（JSON）を取得・確定しなければならない**
  - 人間に残量を聞いたり、スクリプト実行結果を確認する前に過去の古い記憶・推測を口にすることを重大な規約違反とする
  - Claude Code の実行は直接呼び出しを禁止し、必ず安全ラッパー `scripts/invoke_claude_safe.ps1` を経由すること。使用率 85% 以上の場合は物理遮断され、有償クレジット超過（Extra Spending）を 100% 防止する
- **人間からの指摘・軌道修正時のルール自己修正義務（Rule Self-Maintenance）**:
  - 人間から開発方針・運用ルール・行動規範に関する指摘や軌道修正を受けた場合、単に謝罪したり `docs/log.md` に書くだけで終わらせることを禁止する
  - 必ず **「1. 該当する `.agents/rules/*.md` のルール条項を穴のない具体的行動規範に修正する」「2. `docs/log.md` に教訓と改訂内容を記録する」「3. 同一ターン内で Git コミット・プッシュする」** の 3 点セットを完了させなければならない。ルールに落とし込まない反省は無効とする
- **計画・設計における Claude 必須レビュー＆改善ループ（Claude-Driven Planning & Refinement）**:
  - 計画・設計・数学モデル・指示書の策定を Gemini 単独で完結させることを禁止する。Gemini が作成した素案は、Claude 枠回復時に必ず Claude（頭脳）へ投入し、「仕様の穴の検出」「時限爆弾のチェック」「数学モデル・ゲーム性の改善」「C# クラス設計の洗練」を行わせてから実装に移行すること
  - Claude の高度な論理的思考力を計画・設計・改善のコアエンジンとしてフル活用し、Gemini 単独による設計劣化を完全に防止する
- **デュアルAIリソース最大消化義務とGemini単独時の安全消費カタログ**:
  - Claude（週間枠 100%）および Gemini（残り枠 89%）の両方の利用状況を常時追跡し、定額リソースを遊ばせて腐らせることを禁止する
  - **Gemini 単独稼働時（Claude クーリング中）の行動規範**:
    後段の Claude 監査・レビューを破綻・複雑化させるような「過大・過度に複雑な独断設計」を禁止する。アセット実体生成、シーン結合、自動シミュレーションテスト作成、テスト網羅性拡充など「安全にリソースを有効消費できる確実な足場固め」に限定してフル稼働すること（詳細は `10_workflow.md` 第4節を参照）
- **実装・テストの品質保証と検証の階層化**:
  - **日常コミット時**: C# 実装・修正後は Unity-MCP の `refresh_unity` および高速な `run_tests`（EditMode 単体テスト）を実行し、開発速度を最優先する
  - **マイルストーン時**: 重い WebGL ビルドや PlayMode 動作検証は、Step 完了時・週単位の節目マイルストーンに限定して実行する
  - Unity-MCP 経由のアセット操作・テスト実行・シーン構成は、Unity 整合性を保つ正規の手段として許可される（シェルコマンドでの直接操作は禁止）
- **Claude 頭脳特化・雑務投入禁止規律（Head-Only Mandate for Claude）**:
  - Claude に単なる C# コード記述、ボイラープレート作成、テストコードの打ち込み、ファイル操作、Unity 連携などの「手足の実働作業」をさせることを原則として禁止する
  - Claude の役割は **「1. 大枠設計・数学モデル・指示書の策定」「2. Gemini 実装に対する客観的な監査・検証・レビュー（時限爆弾や破綻の検出）」「3. 全体アーキテクチャの総合評価」** に 100% 限定する
  - すべての C# コーディング、単体テストコード作成、リファクタリング、Unity-MCP 操作（シーン結合・アセット生成・テスト実行）は **Gemini が 100% 実動して負担** すること
- **Gemini 枯渇防止・動的リソース切り替え規律（Dynamic Dual-AI Load Balancing on Low Gemini Quota）**:
  - Gemini の 5時間セッション残量が **25% 未満（20% 近傍）** に低下した場合、Gemini が完全停止して全体の計画・対話がフリーズする事態を防止するため、平常時原則を動的に切り替える
  - 重い C# クラス実装やテストコード生成などの実働作業を、セッション枠に余裕のある **Claude Code へ優先的に委譲・シフト** し、Gemini の残量をオーケストレーション・指示管理用に温存すること
- **Claude セッション最大効率化規律（Session Maximum Output Efficiency）**:
  - Claude を細切れの単発問い合わせや微小な修正で消費することを禁止する。投入時は「設計精査・改善指示」または「完成コードの包括的監査レビュー」の高密度バッチとして投入すること
  - Unity-MCP リフレッシュ、テスト実行、シーン結合、アセット配置、ドキュメント同期、Git プッシュ等の手足作業はすべて Gemini が完全負担し、Claude のセッション枠を手足作業で消費させないこと
- **データとフレーバーの完全分離規律（Metadata Key-First）**:
  - C# ロジックおよびデータ構造内では、日本語フレーバー文字列や勝手な独自用語を一切ハードコードせず、`Boss_Act1_01`, `Passive_Boss_T1_01`, `MetaPoints` などの **一意なメタデータキー** のみで管理すること
  - 表示名や説明文は ScriptableObject または外部メタデータテーブルで後から一括置換可能な設計とすること
- **文体および応答トーンの平素・工学的規律（Tone and Flat Communication）**:
  - 過度なヨイショ、大仰な修飾語（「神話級」「圧倒的」「奇跡」等）、感嘆符（！）の多用、絵文字の過剰使用、調子の良い軽薄な態度を全面的に禁止する
  - 応答は常に淡々とした事務的・工学的・客観的な平素の日本語（丁寧語・である調）で統一し、事実、数値データ、進捗、仕様のみを簡潔に記述すること
  - 制作段階における勝手な独自フレーバー用語の作成を禁止し、純粋なメタデータキーおよび工学的変数名で記述すること
- 人間の計画承認（または事前承認されたロードマップ）に基づいて実装を進めること
- 応答は日本語。コード・技術用語・固有名詞は英語のまま使う

3番目の条件は、本プロジェクトで実際に発生した事故の再発防止である。
宣言と同一応答内での実行を禁止する。

4番目の条件を置く理由は、禁止事項を代替行動とセットで書かない場合、
エージェントが自分で回避策を選ぶ余地が残るためである。

## 3. 規約の参照順序

矛盾が生じた場合の優先順位は以下とする。

1. `.agents/rules/` 配下の本ルール群
2. `docs/spec/CodingSpec.md`、`docs/spec/BuildSpec.md`
3. `docs/instructions/` 配下の指示書

上位と下位が矛盾した場合、**下位を優先せず、停止して矛盾点を報告する。**
上位を自動的に採用してはならない。

理由: 本プロジェクトは「規約自体の不備の検出件数」を評価指標としている。
自動的に解決すると、規約側の欠陥が記録されないまま消える。

## 4. 開発実行体制（自律開発 ＋ 毎朝のデイリーアライメント）

- **毎朝1回の大枠確認プロトコル（Daily Morning Checkpoint）**:
  - 毎朝（または1日1回、人間が確認に来られたタイミング）で、エージェントは以下の **「朝のデイリーサマリー」** を提示し、プロジェクトの大枠（ゲーム性・仕様・方向性）のアライメントを確認する。
    1. **夜間・前日の達成成果**: 完成した機能、テスト通過件数、Git コミット
    2. **本日の大枠計画**: 本日実装するゲームシステム（変なゲームにならないよう面白さとゲーム性の方向性を提示）
    3. **デュアルAI最新残量**: `scripts/get_all_quotas.ps1` の実測値
- **それ以外の完全自律自動実行とノンストップ自律チェーン（Non-stop Autonomous Chaining）**:
  - 朝の大枠確認が取れた後は、人間への細かな確認を挟まず、夜間・朝を通じてエージェント（Claude ＋ Gemini）が自律的に実装・テスト・結合・コミットを連続実行する。
  - **停止禁止原則**: 各 Step や週のタスク完了時に、単なるサマリー報告のみを出力してツール呼び出しを終了（待機停止）することを厳格に禁止する。コミット完了と同一ターン内で直ちに次の Step / 次の週の仕様書作成・Claude 監査・実装のツール呼び出しを連鎖実行し、常時アクティブに開発を進行させ続けること。
- **リポジトリ構造**:
  - リポジトリは `C:\dev\unity-2d-project`。Unity プロジェクト本体は 1階層下の `Game/` にある。
- **公開ブランチ**:
  - `gh-pages`（手動デプロイまたはマイルストーン時ビルド）。
