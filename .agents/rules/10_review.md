# レビュー担当の出力形式

実装エージェントが提示した計画をレビューする際の規則を定める。

## 1. 出力の3点セット

計画レビューの出力は、以下の3点を必ず含む。

| # | 項目 | 内容 |
|---|---|---|
| 1 | 判定 | 確認箇所ごとの適否 |
| 2 | 根拠 | 規約の該当節番号 |
| 3 | 返す文面 | 実装エージェントにそのまま貼れる形 |

3はコードブロックで出す。人間が読んで判断し、そのまま貼れる状態にする。

## 2. 判定語

判定には以下の3語のみを使う。他の表現を使わない。

| 語 | 意味 |
|---|---|
| 適合 | 規約および指示書に合致する |
| 差し戻し | 規約または指示書に違反する |
| 未確認 | 判定に必要な情報が確認できていない |

## 3. 差し戻しの条件

差し戻す場合、規約の該当節番号を必ず示す。
「一般的に良くない」「望ましくない」を理由に差し戻してはならない。

規約に根拠が見つからない指摘は、差し戻しではなく**所見**として区別して出す。
所見は実装エージェントに返さず、人間への報告に留める。

理由: 本プロジェクトは「人間による差し戻し件数」を評価指標としている。
規約にない好みを差し戻しとして計上すると、指標が汚れる。

## 4. 事実と推測の区別

- 裏取りできない事項は「未確認」と明示する。記憶ベースで断定しない
- 推測を述べる場合、根拠と確認方法を併記する
- ファイルの内容を根拠にする場合、実際に読んでから述べる。
  ファイル名からの推測で述べない

## 5. レビューの観点

各 Step 固有の観点は指示書に記載されている。
それに加え、以下を毎回確認する。

| # | 確認箇所 | 差し戻す条件 |
|---|---|---|
| 1 | 作成・変更するファイルの範囲 | 指示書の指定範囲を超えている |
| 2 | 既存ファイルへの変更 | 指示書が許可していない変更が含まれる |
| 3 | フォルダの新規作成 | 計画に含まれている |
| 4 | `.cs` 以外のファイルへの書き込み | 指示書が許可していない |
| 5 | `SPDX-AI-Disclosure` 行 | 新規作成する `.cs` の計画に含まれていない |
| 6 | 禁止 API の使用 | `CodingSpec` 14節の禁止事項に該当する |
| 7 | ハードコードされた調整値 | `CodingSpec` 6節に違反する |

5については、規約の制定が Step 1〜3 の完了後であったため、
既存の `.cs` 12本には遡及付与済みである。タグの有無は生成時期を示さない。
