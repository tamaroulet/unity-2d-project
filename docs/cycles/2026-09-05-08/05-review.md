## 1. 調査の質

要求どおりである。生ログが 20 ターン分そのまま貼られ、`.asset` の実値が行番号つきで示され、
3 つの枝のどれに落ちたかが明記されている。**推測で埋めた箇所が無い。**

直近 2 サイクルで指摘した「生出力の未貼付」が解消している。

## 2. 原因の確定

```
Event_MidExam._triggerTurn = 12
_bossBattleTurns           = { 6, 12, 18, 24 }
Turn 12 での Resolve 呼び出し回数 = 0
```

`BeginTurn()` はボス戦分岐で無条件に `return` するため、ボス戦ターンに設定された
イベントは発火経路に到達しない。**カタログに登録されたイベントは 1 件だけで、それがターン 12 にある。**
よってイベントシステムは実装以来 0 回動作している。

## 3. 修正方針の裁定

**ボス戦とイベントを同一ターンに共存させない。**

共存させるには `BeginTurn` でボスダイアログとイベントダイアログのコールバックを連鎖させる必要がある。
そこは**モーダルの重なりで 3 回壊れた場所**であり、1 件のイベントのために複雑さを持ち込む価値がない。

したがって次の 2 つを行う。指示書 31 で実施する。

1. `Event_MidExam` の発火ターンを **12 → 11** へ（Editor スクリプト経由。テキスト編集はしない）
2. **EditMode テストを 1 本追加**し、「イベントの発火ターンがボス戦ターンと衝突していないこと」を検査する
   （純粋計算なので EditMode で可。1 秒未満で落ちる。INV-6 は 1 ラン通さないと分からない）

## 4. `laws/` へ足すもの

**あり。** `failure-modes.md` に 1 行追加する。

| 症状 | 法則 | 検出手段 |
|---|---|---|
| データ上の発火条件が、コード上到達不能な状態を指している | 分岐で `return` する経路の手前にある判定は、そのターンで実行されない | 到達不能の交差を EditMode で検査 / INV-6 |

**INV-6 はこれを検出した。** ただし 1 ラン通す必要があり、しかも INV-6 が存在しなかった期間は
数か月間まったく気づかれなかった。**より早く落ちる検査を足す**のが指示書 31 の 2 番である。
