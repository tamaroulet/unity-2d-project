# 指示書 31: イベントを発火させ、到達不能な設定を早期に検出する

```
ROLE: Executor
BRANCH: main
判断: docs/cycles/2026-09-05-08/05-review.md
前提: 指示書 30 の完了後に着手する。同時に走らせない（どちらもシーンに触れる）
```

## 目的

イベントシステムが実装以来 0 回動作していない。原因は確定済み。

```
Event_MidExam._triggerTurn = 12
_bossBattleTurns           = { 6, 12, 18, 24 }
BeginTurn はボス戦分岐で無条件 return するため、ターン 12 で Resolve に到達しない
```

**ボス戦とイベントは同一ターンに共存させない。** 共存にはダイアログのコールバック連鎖が必要で、
そこはモーダルの重なりで 3 回壊れた場所である。1 件のイベントのために持ち込む複雑さではない。

---

## 1. 実装方針

### A. 発火ターンを 12 → 11 へ

`Game/Assets/Data/Events/Event_MidExam.asset` の `_triggerTurn` を **11** にする。

**`.asset` のテキスト編集は禁止。** `Game/Assets/Editor/` の Editor スクリプト経由で、
`SerializedObject` を通して書き換えること。既存の generator を**再実行しない**（GUID が変わる）。
1 フィールドだけを書き換える小さな Editor メニューを足してよい。

ターン 11 はボス戦ターンではなく、空いている。

### B. 到達不能な設定を EditMode で検出する

`Game/Assets/Tests/` 直下に EditMode テストを 1 本追加する。

> `GameEventCatalogSO` に登録された全イベントについて、
> `TriggerKind == Turn` のものの `TriggerTurn` が、ボス戦ターン `{6, 12, 18, 24}` と衝突しない。

- **純粋計算なので EditMode で可**（規約適合。SO のモックを組み立てず、実アセットを読む）
- ボス戦ターンは `GameFlowController` の既定値と同じ値をテスト側に定数で持つ。
  **プロダクションコードに公開用のフィールドを足さない**
- 失敗時は「どのイベントがどのターンで衝突しているか」を名指しする

**なぜ INV-6 で足りないか**: INV-6 は 1 ラン通さないと分からない。
この検査は 1 秒未満で落ちる。**早く落ちるほど安い。**

### C. `laws/failure-modes.md` に 1 行足す

| 症状 | 法則 | 検出手段 |
|---|---|---|
| データ上の発火条件が、コード上到達不能な状態を指している | 分岐で `return` する経路の手前にある判定は、そのターンでは実行されない | 到達不能の交差を EditMode で検査 / INV-6 |

`laws/` の 150 行上限を超えないこと。超えるなら足さずに報告する。

## 2. やってはいけないこと

- `BeginTurn` のボス戦分岐に手を入れない。**共存させない**
- `_bossBattleTurns` を変更しない
- `.unity` / `.asset` / `.meta` のテキスト編集。**`.unity` を読まない**
- イベントを新規に追加しない（仕様判断は人間が行う。既存 1 件を発火させるところまで）
- `EventResolverSO` / `GameEventSO` のロジック変更
- 不変条件・機械判定・スナップショットの仕組みへの変更
- 指示書 30 と並行して走らせない

保護対象は従来どおり（`docs/laws/**` は §1-C の 1 行追加のみ許可）。
