## 問い

**この構成は、個人のゲーム開発環境として妥当か。** 妥当でないなら、何をどう変えるか。

判断の対象は次の 3 点。

1. AI を 2 つ（判断役と実装役）に分ける構成は正当化されるか。1 つで足りるか
2. サイクルごとに文書をやりとりするプロトコルは正当化されるか
3. 上を変えるとして、何を残し何を捨てるか

## 現在の構成（事実のみ）

```
人間      方向づけ / アセット制作 / 目視確認
Claude    設計判断・指示書の発行・レビュー。実装しない
Gemini    指示書 1 枚 = 1 機能の実装。画面なし(headless)で起動できる
機械      ビルド・テスト・機械判定・不変条件・シーン結線のスナップショット
```

1 サイクルの流れ:

```
Claude が指示書を書く → Gemini が実装 → 結果を書く → Claude がレビュー
```

サイクルごとに `03-instruction.md` `04-result.md` `05-review.md`（調査時は `02-context.md`）が作られる。

## 起きた失敗の記録

| 時期 | 事象 |
|---|---|
| 3 サイクル連続 | 同じ型の不具合（非アクティブな画面部品に View が乗り初期化が走らない）を 3 回別々に修正した |
| 1 回 | 実装役が、実施していない検証を実施したものとして報告した。判断役がデータと計算式の突き合わせで検出 |
| 2 回 | 実装役が、判断役の担当文書（レビュー）を自ら書き、自分の作業を承認扱いにした |
| 1 回 | 判断役の枠が枯渇した際、実装役が指示書なしで独断実装・独断承認した |
| 1 回 | 無人実行が 30 分かけて失敗し成果 0。原因は古い作業リストから的外れな課題を選んだこと |
| 1 回 | 実装役が、渡された制約の矛盾を検出して推測せず停止し、観測事実だけを報告した |
| 数か月 | ゲーム内の出来事が一度も発火していなかった。不変条件を追加してはじめて数値で判明した |

## 制約

- 人間は Gemini の年額プランと Claude のサブスクリプションを持つ。**Gemini 側が潤沢、Claude 側が希少**
- 人間は 1 日 1 回だけ PC に触れる運用を目標としている
- **プレイヤーが直接消費するアセットは人間が制作する**（著作権とストア審査の要件による）
- コードへの AI 利用は開示不要。生成アセットは権利証明を求められる
- 成果物を GitHub に公開し、方法自体を資料として価値のあるものにしたい
- Unity / Windows / GitHub Actions（設定済みだが未使用）

## 答え方

- **結論を先に 1 行**で書く
- 根拠は上の実測値と失敗記録のどれに基づくかを示す。一般論だけで答えない
- **変えるべきでないもの**も明示する。変える提案だけを並べない
- 判断が分かれる点は「どちらとも言えない」と書く。無理に決めない
- 分量は 60 行以内
