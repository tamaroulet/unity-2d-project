# Deep Research 調査指示書 04：AI主軸ゲーム開発のアーキテクチャ・設計フレームワーク調査

## 1. 調査の背景と目的

LLM（Claude Code, Gemini, Cursor 等）を主軸として Unity ゲーム開発（特に 2D ターン制・ローグライク等のロジック駆動ゲーム）を行うプロジェクトにおいて、以下の構造的課題に直面している：

1. **Runtime Blindness（実行時盲目）**: LLM は C# のテキストしか読めず、Unity の Scene, Prefab, Inspector のシリアライズ参照が見えないため、エディタ専用ハック（`#if UNITY_EDITOR` 内での `AssetDatabase` や `transform.Find`）に依存して製品ビルド（WebGL 等）を破壊する。
2. **密結合による自律性の崩壊**: UI と ロジックが密結合していると、AI が一部を改修した際にドミノ倒し式に全体が壊れ、コンパイルエラーや例外が無限増殖する。
3. **当てずっぽうなプロンプト駆動の限界**: 単に AI に「機能を作って」と指示するだけでは、16時間以上の自律稼働でアーキテクチャが崩壊する。

**目的**:
2024年〜2026年現在において、インディー開発者、研究機関、ゲームスタジオ、OSSコミュニティが **「AIエージェントにゲームを作らせるために、どのようなアーキテクチャ・設計パターン・ツール接続を採用して成功しているか」** の具体的かつ実用的な先人たちの知見を網羅的に調査・抽出する。

---

## 2. 重点調査項目（Research Axes）

### 軸1：AIエージェントと Unity の接続フレームワーク（MCP / 視覚の獲得）
* 2025〜2026年における **Model Context Protocol (MCP)** を用いた Unity エディタ統合の最新事例と OSS 実装。
* AI が「テキストしか読めない盲目状態」を脱し、シーンヒエラルキー、インスペクタ参照、コンソールログ、ゲーム実行状態を安全に読み取るための標準プロトコル。
* Unity 公式の Unity AI / Muse / Sentis や、サードパーティ製 Agent ツールキット（coplaydev/unity-mcp 等）のアーキテクチャ設計。

### 軸2：AIが壊しにくいゲームアーキテクチャ・パターン
* **ScriptableObject (SO) 駆動アーキテクチャ**:
  * Ryan Hipple 提唱の SO Architecture（EventChannel, Variable, GameEvent）が、AI 開発においてどのように機能するか。
  * UI、ロジック、データ（ステータス、敵、スキル）を完全に疎結合にし、AI が「1つの SO と 1つのハンドラ」だけを自律追加できる構造の具体例。
* **ステートマシン（FSM）とフェーズ管理**:
  * ターン進行やゲームフェーズ（コマンド入力、戦闘、ドラフト、エンディング）を AI に実装させる際、どのパターンが最もバグりにくいか。
* **データ指向 / ルールベース設計**:
  * コードではなく ScriptableObject や JSON/YAML などの純粋データ定義だけでゲーム要素（スキル、イベント、レリック）を拡張できるパイプライン。

### 軸3：国内外の「AI-Native Game Development」実例・先行研究
* AI エージェントを主軸・完全自律・半自律で活用して完成・公開に至った商業インディーゲームやプロトタイプの事例分析。
* 開発者たちが直面した「最大の壁」と、それを解決した工学的工夫（ルールファイル、ハーネス、ディレクトリ規約）。

---

## 3. 要求成果物（Deliverables）

1. **「AIが絶対に壊せない」Unity 疎結合アーキテクチャの具体的設計図（C# サンプルコード付き）**
   - イベント送受信（SO Event Channel）
   - ゲームフェーズ遷移（GameFlow State）
   - データ追加パイプライン（新コマンドや新レリックの追加方法）
2. **Unity MCP を用いた AI ツール連携の推奨セットアップ**
   - AI が触るべき MCP ツール（Hierarchy, Console, TestRunner 等）と、触らせてはならない領域。
3. **先人の失敗・アンチパターン集**
   - 「これをやると AI は必ずコードを壊す」という具体的パターン（Singleton の乱用、Update 内検索、静的参照など）。
