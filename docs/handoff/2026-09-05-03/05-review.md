## 3. 指摘（次サイクルで直すこと。差し戻しではない）

### 3-A. 削除行を「変更行数」に数えると、撤去作業が必ず FAIL する

cycle 2026-09-05-04 で実際に起きた。

```
FAIL Changed lines: 433 lines (added 54 / deleted 379 > 300)
```

379 行は指示書 23 が明示的に命じた UI Toolkit パイロットの撤去である。
**指示どおりに消したら FAIL になる**のは判定として誤っている。

停止条件の趣旨は「1 タスクで書きすぎるな」であって「消すな」ではない。
**追加行のみを 300 行の判定対象にし、削除行は併記に留めること。**

### 3-B. `Snapshot` の表記が矛盾している

同じく cycle -04 の出力。

```
PASS Snapshot: docs/snapshot/scene_bindings.txt diff (... 10 insertions(+), 10 deletions(-))
```

差分があるのに `PASS` と出ている。シーンを変更するサイクルでは差分が出るのが正しいので、
判定自体は妥当だが、**表記が読み手を誤らせる。**
差分ありは `SKIP`（判定対象外）とし、行数と内訳を併記する形へ変えること。
