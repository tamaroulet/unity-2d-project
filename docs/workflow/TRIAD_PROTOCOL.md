# 3者協調作業フロー規約（Triad Protocol）

本規約は `.agents/rules/development-rules.md`（宣言的制約）の**運用手続き**を定める。
両者が矛盾する場合は `development-rules.md` が優先する。

## 0. 目的

主導権を**Claude に固定**し、Gemini の単独判断・勝手な提案・方針変更を排除する。
すべての作業は「人間の承認済みの大枠」に由来しなければならない。
承認を経ていない作業は、たとえ正しくても**規約違反**として差し戻す。

## 1. 役割の固定

| 主体 | できること | 禁止事項 |
|---|---|---|
| **人間（ディレクター）** | 大枠の承認・却下・優先順位の決定。Unity エディタ操作、Inspector アサイン、目視確認 | — |
| **Claude（アーキテクト）** | 大枠提示、設計判断、指示書の発行、検証、レビュー | 承認前の指示書発行。実装（コードを書く作業は原則 Gemini に委譲） |
| **Gemini（実装者）** | 指示書の Tasklist を忠実に実装。指示書内の作業は確認なしで自動実行してよい | 別解の提案、方針変更、指示書にないファイルへの書き込み、独断でのリファクタ |

## 2. 必須サイクル（1ターン = 1周）

```
① Claude → 人間 : 大枠の確認（承認を求める）
② 人間  → Claude: 承認 / 却下 / 修正指示
③ Claude → Gemini: 確定指示書の発行（②の承認後、"次のターン"で）
④ Gemini → Claude: Tasklist 実装 → コマンド出力を貼って停止・報告
```

### ① Claude が人間に提示するもの（4点セット・省略不可）

1. **方針**: 次に何を、なぜやるのか（1〜3行）
2. **選択肢**: 案A / 案B / 案C を、それぞれ「得るもの・失うもの・所要」付きで。推奨案を明示する
3. **リスク**: 失敗しうる点と、失敗時の撤退方法
4. **セッション残量**: Claude 週間枠 / 5h枠、Gemini 週間枠 / 5h枠の実測値

### ② 人間の承認

人間の返答に「承認」「OK」「案Aで」等の明示的な選択が含まれるまで、③へ進んではならない。
沈黙・曖昧な相槌は承認ではない。

### ③ 指示書の要件（すべて満たさない指示書は発行禁止）

- **対象ファイルの絶対パス**と、触ってよいファイルの**完全な列挙**（列挙外は書き込み禁止）
- **完全一致コード**（差分ではなく、貼り付けられる形。置換なら before/after 両方）
- **行番号**（挿入・置換位置）
- **停止条件**（例: 同一エラーを2回直して直らない／300行超／指示書にない設計判断が必要になった）
- **検証コマンド**（実行するコマンドと、期待される出力）
- **完了報告フォーマット**（下記 ④）

指示書は `docs/cycles/` に 1 枚 = 1 機能で保存し、コミットする。

### ④ Gemini の完了報告フォーマット

```
指示書: docs/cycles/YYYY-MM-DD-NN/03-instruction.md
実施: Tasklist 1/2/3 完了（または N で停止）
--- コマンド出力 ---
（検証コマンドの生の出力をそのまま貼る）
---
停止条件への抵触: なし / あり（内容）
```

自然言語の進捗宣言（「うまくいきました」「改善しました」）は報告として無効。
**コマンド出力とコミットハッシュのみが進捗である。**

## 3. 逸脱時の扱い

| 逸脱 | 対応 |
|---|---|
| Gemini が指示書外のファイルを変更した | Claude が `git checkout` で該当変更を破棄し、人間に報告 |
| Gemini が別解・方針変更を提案した | 提案は受理せず、①に差し戻して人間の判断を仰ぐ |
| Claude が承認前に指示書を発行した | 指示書を撤回し、①からやり直す |
| 承認済みの大枠から作業が外れた | その場で停止し、①に戻る |

## 4. 安全ハーネスとの関係

既存の散文による 4 段階ゲート（Fix Gate Protocol）は廃止され、`nightly_gate.py` の判定コード（ポリシー検査・テスト判定・連続 REJECT 停止）へ移行された。
本規約における対応は以下の通り。

- ①②（大枠提示と承認） → 上流確認
- ③④（指示書発行と実装） → 実装
- ハーネスの判定（`nightly_gate.py`） → 下流検証

## 5. 記録

各サイクルの「大枠 → 承認 → 指示書 → 報告」は `docs/log.md` に日付単位で追記する。
承認が口頭のみで文面に残っていない作業は、完了として記録しない。
